# Delegate to Local Model Workflow

> **Agent role:** Gemini in Antigravity (`agent:gemini`)  
> **Source:** `AGENTS.md` §6, `coordination/README.md` §1, and `docs/reference/Local_Agent_Setup.md`

This workflow defines the rules, boundary checks, execution steps, and verification procedures for delegating bounded, mechanical tasks to the local Ollama model (`qwen3.5:9b`) on the founder's workstation.

---

## 1. When Delegation is Allowed

Delegation to a local model is permitted **only** for bounded, mechanical subtasks that have a deterministic source of truth and an automated verifier:

- **Docstring passes:** adding docstrings to utility functions or scripts adhering to PEP 257.
- **Fixture generation:** generating JSON/Python test fixtures directly from canonical seed data tables (e.g. DM §8).
- **Format conversions:** mechanical conversions between formats (e.g. schema to Pydantic, table to markdown).
- **Boilerplate generation:** generating repetitive dataclasses, enum mappings, or schema models where the source specification is frozen.

---

## 2. When Delegation is Forbidden

Delegation is **strictly forbidden** for:

- **Forbidden paths:** anything under `docs/specs/`, `docs/runbooks/`, or `AGENTS.md`.
- **Protected subsystems:** financial transaction safety, consent management, audit log hash chaining, or supervisor state transitions.
- **Judgement calls:** architectural decisions, conflict resolution, or interpreting ambiguous requirements.
- **Autonomous git actions:** local models never make git commits directly; Gemini manages git branches, PRs, and coordination.

---

## 3. How to Structure the Prompt File

Create a dedicated prompt file (e.g. in `scratch/` or a temporary file) following these guidelines:

1. **Explicit constraints:** Specify exact formatting (e.g. "Output valid Python code only. Do not include markdown code fences or conversational prose.").
2. **Context via `--input`:** Keep instructions in the prompt file and pass reference documents, DDL, or source code via `--input <path>`.
3. **Deterministic expectations:** State the required output format and field requirements explicitly.

Example prompt file (`scratch/prompt_docstrings.txt`):
```text
Add PEP 257 docstrings to all functions in the provided Python file.
Preserve exact function signatures and implementation logic.
Output only the complete, updated Python code.
```

---

## 4. Execution

Invoke the harness from the repository root:

```powershell
python tools/local_model.py --prompt-file <path_to_prompt> --out <output_path> [--input <file1> ...] [--model qwen3.5:9b]
```

### Self-Test Pre-check
Before running a batch task, verify the local model harness:
```powershell
python tools/local_model.py --selftest
```

---

## 5. Verification Requirements

Gemini remains 100% accountable for all generated output. **Never commit output without explicit verification:**

1. **Syntax / Compilation:** Run `python -m py_compile <file>` or syntax parsers.
2. **Linting & Formatting:** Run `uvx ruff check <file>` and ensure zero errors.
3. **Diff Review:** Inspect `git diff` to confirm the local model did not introduce regressions, hallucinated imports, or unwanted logic changes.
4. **Automated Tests:** Execute the relevant test suite or assertions against the generated artifact.

---

## 6. PR Handoff & Transparency

Every pull request that includes code or documentation generated by a local model must state so in the PR handoff block under `### Assumptions made`:

```markdown
### Assumptions made
- Local model (`qwen3.5:9b`) generated <component or file>; verified by Gemini via <command>. Reversible: yes.
```
